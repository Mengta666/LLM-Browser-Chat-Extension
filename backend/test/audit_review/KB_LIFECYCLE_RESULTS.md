# 知识库一致性改造验收

日期：2026-09-16。分支：`agent-slim`，改造基线 `d62bf1a`；本文对应未提交工作区。

## 范围与实现

本轮修复 F2、F11、F12、F13，并为同一发布版本的邻居扩展修复 F4。没有清空用户知识库，没有修改 `.env`，没有提交或推送。

- 每次索引生成 `index_run_id`，片段先以 `valid=false` 暂存，逐批检查取消状态，完整校验后条件发布；稳定片段 ID 避免同批重试重复写入。
- SQLite 是对外可检索性的最终依据。粗召回后、邻居读取及最终返回前核验库、文档、同步状态和已发布版本；Qdrant 单独激活不代表发布成功。
- 删除先在 SQLite 同事务隐藏、取消待处理文档，再同步向量；错误父库或错误 owner 请求不能修改数据。KB 操作只匹配 `kb_chunk`，不误动同集合中的长期记忆。
- 恢复只恢复同次整库删除级联的文档，保持单独删除状态；向量校验/同步完成后才原子恢复元数据。失败返回 503，持久化意图可由手动重试或后台恢复继续处理。
- 运行中按 KB 串行协调关键操作；每 30 秒重试待同步状态。启动时将被重启打断的索引标为失败，不使用可能不完整的暂存内容。
- 首次迁移先备份原 SQLite，DDL 与状态迁移统一事务。旧索引兼容缺少版本字段的 payload，只有完整性核验通过才开放。
- 前端检查 HTTP 与业务失败，展示索引中、待同步、失败待清理和恢复未完成；上传/轮询固定原 KB，迟到的文档列表不能覆盖用户新选中的库。

## 边界与剩余问题

- 本方案是单进程协调、持久化意图和检索准入，不是 SQLite/Qdrant 分布式强事务；不承诺多 worker 或跨进程索引协调。
- 远端调用已经发出时不能撤回；失效状态先阻断检索，物理同步允许延后。已经返回给调用方的内容无法事后撤回。
- 重启不自动续传原文件；中断索引需重新上传。缺片的旧 indexed 文档需要人工核验，不能仅点还原就凭空补全片段。
- 迁移事务保护是在本轮真实流程后补上的启动阶段改动，已通过隔离故障注入；运行中的进程要在下次重启加载。没有为了验证而回退用户真实数据库。前端文件需重新加载扩展才能生效。
- 剩余 **12 个 xfail** 属于本轮范围外的既有问题，包含精排零分回退、旧聊天协议、非法工具参数、引用 HTML、日志查询和旧请求时限；不能理解为全仓库缺陷已清零。
