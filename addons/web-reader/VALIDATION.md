# Web Reader 验收记录

## 0.2.0：结构提取与本轮预算

本轮未提交、未推送，未改真实配置、密钥、端口及 SearXNG，未重启正式后端。测试使用隔离本地正文服务、数据库及模型客户端，关闭长期记忆写入。远端 reader 必须同步更新才能应用结构修复。

- 独立正文服务：61 项通过，包括行内文字顺序、中英文条件、嵌套列表代码缩进、表头、偏移、原有 SSRF/鉴权/超时终止保护。
- 后端回归：469 项通过，4 项原有预期失败；覆盖 server/client × stream/nonstream、一次提问内共享预算、下一提问重置、摘要及缓存、完整请求包装预算、一次受控长度重试和普通 400 不重试。
- 前端 Node：124 项通过；Playwright 隔离 Chrome 的 42 项 DOM 断言通过，包括“读取/纳入”区分、未纳入原因、旧服务提示、引用转义及历史恢复。
- Compose 官方 schema 静态验证和独立环境 `pip check` 通过。当前本地无 Docker，未重新构建服务器容器。

### 真实页面及实际模型请求

新版抓取 Python 下载页、asyncio 文档和 MDN HTTP 429 均成功，分别得到 18886、46329、1642 字符和 35、83、17 个结构块。数值仅代表本次页面快照。

旧版原文序列化和选段会丢失 TaskGroup 的基础异常例外。新版在同一段内保留异常名称及处理规则；该复现查询在 1000～6000 的节选额度下均保留规则。更低预算仍不能保证覆盖所有限定条件，输出显式标记节选和省略，不能当作全文。

真实 SearXNG 链路中，HTTP 429 成功读取 3 篇正文并完成回答；另外的 TaskGroup/gather 查询多次遇到引擎限流、CAPTCHA、超时，不能记为正文全链路成功，没有修改搜索服务绕过这些失败。

为隔离搜索波动，另用三份固定公开文档作为**测试搜索结果**，实际进行下载、正文提取及真实模型调用。TaskGroup → gather 追问 → HTTP 429 三轮均完成，分别纳入估算 3769、3788、3718 tokens，均低于每次用户提问 6000 的额度；六次模型请求最高估算 9039，服务返回最高实际 `prompt_tokens=6974`，配置输入额度为 55296。异常例外规则实际进入模型请求，回答明确描述了原异常重新抛出。

固定候选集测试不代表真实 SearXNG 搜索验收，也不是严格准确率 A/B。模型仍出现过对 TaskGroup 任意嵌套任务追踪范围的过度概括；本轮未引入语义复核，不能保证回答无误。

### 计数和部署边界

当前模型网关的 `/tokenize` 探测返回 404，使用 cl100k_base × 1.25（不可用时启发式）并保留输出和安全余量，非目标模型精确计数。图片仍采用粗略估算。严格匹配实际模型 tokenizer、极限多模态输入和服务端真实最大窗口还需单独核对。

本地原始测试材料位于忽略的 `output/web-reader-020-live/`、`output/web-reader-020-fixed/`；Windows 沙箱管道拒绝的首次运行单独保留在 `output/web-reader-020-validation/`，不计成功。详细部署步骤见 [部署说明](../../deploy/README.md)。

### 真实网页和模型链路

临时启动独立正文服务，检查实际模型请求包含正文，不以卡片显示“成功”代替链路验证。

三份公开页面均成功提取：

| 页面 | 提取字符数 |
| --- | ---: |
| [Python 下载页](https://www.python.org/downloads/) | 74225 |
| [Python asyncio 文档](https://docs.python.org/3/library/asyncio-task.html) | 46768 |
| [MDN HTTP 429](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/429) | 2488 |

实际聊天包括 1 轮仅摘要对照，以及开启正文后的 3 轮连续对话：TaskGroup 失败行为 → 追问 gather 区别 → 切换 HTTP 429 话题。四轮均完成；开启正文的三轮模型工具输入实际含正文，单轮正文读取分别为 2/3、1/3、3/3 页。

现场出现过 `connection_error`、`http_403`、`fetch_timeout`，均显式保留失败状态并降级为摘要，没有让整轮聊天失败。临时服务已退出；用户原有服务、真实配置和业务数据库未更改。

对照组查询由模型生成，不是固定查询和固定候选集的严格 A/B 试验；不能据此宣称提速或准确率提升。模型回答仍出现过概括过度、引入旧 issue、遗漏异常类型等问题，说明“读取正文”不等于“语义正确”。本次没有重新引入强制语义核对，也不保证模型总能识别最新版本。
