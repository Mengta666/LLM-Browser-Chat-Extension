# PDF 知识库

本模块负责文档层，不改变浏览器自动化动作、长期记忆和会话压缩。OCR 服务只处理单页请求，任务与检查点统一保存在后端。

## 数据流

1. 上传按 1 MiB 分块接收，校验 50 MiB 上限和 PDF 页数，计算 SHA256。
2. 原 PDF 移入受控目录；文档与解析任务一起写入 SQLite。
3. Worker 有限并发渲染页面、调用远端解析，保存原始 JSON、坐标、阅读顺序、表格行及块文本。已知输出截断记录为失败页，不发布；错误、尝试次数和已完成页保留。
4. 页面全部覆盖后，从保存的原文建立独立结构版本：书签优先，其次显式章节编号，最后才使用版面线索；文档标题不冒充章节，无法判定的内容保留有界段落组。命题、证明、表格、公式形成内容单元，结构关系带原文证据范围及推断依据，不改写原块。embedding `/tokenize` 计算完整检索输入，长块按字符范围分片。
5. 分批向量化并写入未发布索引，记录检查点；确认向量数量完整后原子切换 SQLite 发布指针。查询再次核验指针，不依赖跨库事务。
6. 多路召回合并精确编号、字面入口、首页元信息、Dense＋Sparse 候选，精排后按同文档、同解析版本的准确来源范围去重，再限量提供证据；完全包含的候选保留覆盖完整的一条，部分重叠或不同文档不能合并。各路、融合、精排和最终证据数量独立配置。显式公式编号直接定位正文和编号，避免检索到证明段冒充公式；已知页块可以直接读取。

## 存储与恢复

- `kb_docs` 保留旧 ID，新增原文件、SHA256、页数、解析及索引发布指针。
- `kb_parse_versions`、`kb_pages`、`kb_blocks` 保存任务、页和内容块；表格行、合并信息放在块内 JSON。
- `kb_index_runs`、`kb_chunks`、`kb_chunk_sources` 保存可重建索引及准确来源；`kb_identifiers` 保留完整编号和前导零。
- `kb_structure_versions` 保存结构配置、检查点和发布状态；`kb_document_nodes` 保存层级与类型；`kb_node_sources` 保存准确字符范围；`kb_node_relations` 区分条件、解释、明确证明目标和普通引用。关系不能替代语义验证。
- 解析、结构、索引各自有版本，索引记录绑定结构版本。结构和向量全部就绪才切换发布指针；未发布版本不参与正常读取。重建索引复用 OCR，不修改旧 `kb_blocks.parent_id` 或已发表原文。新请求选择当前发布版本，进行中的请求固定原组合。
- 解析失败不丢已完成页；索引失败不重新识别已有页。取消使执行租约失效，迟到结果不能发布。
- 服务重启只标记中断，不自动恢复。点击恢复会复用检查点；解析配置或识别版本变化不能混用旧页。
- 重新解析产生新解析版本；只换 embedding 可重建索引。已有引用仍读取其原发布版本，文档删除后所有版本都立即禁止读取。
- 删除到回收站保留原文件；彻底删除才移除文件、结构和索引。此操作不可恢复。

## 接口

所有接口继续绑定当前后端的知识库用户范围，不接受任意本地路径。

| 接口（前缀 `/v1/kb/{kb_id}/docs/{doc_id}`） | 行为 |
| --- | --- |
| `GET /status` | 阶段、已解析页数、索引进度、旧版本是否可用、失败页与尝试次数、截断未知页数 |
| `POST /cancel` | 停止当前任务，保留检查点 |
| `POST /retry` | 显式恢复 |
| `POST /retry?reparse=true` | 新建解析版本 |
| `POST /retry?reindex=true` | 复用解析结果重建索引 |
| `GET /outline` | 默认逐块目录；`view=tree` 配合 node_id/depth 浏览层级，`view=sections` 保留旧章节视图；支持版本及分页 |
| `GET /read` | node_id、页、块、章节或 formula_number；字符/表格行精确读取；node 使用 cursor 和 block_offset 原顺序续读，不能混用其他定位；HTTP 单次最多 16000 字符 |
| `GET /file` | 原 PDF |
| `GET /pages/{page}.png?parse_id=…` | 与保存坐标对应的原页图 |

模型使用 `kb_list_documents`、`kb_get_document_outline`、`kb_search`、`kb_read_document`。读取工具使用 `targets` 数组，每项按 `mode` 选择 `block/range/rows/page/section/formula/related`；模型不再同时组合 `include_related` 与偏移。旧 HTTP/工具参数仍做兼容：关联展开允许省略偏移或 `offset=0`，与非零偏移、end、行范围混用会明确报错。新旧定位方式不能同时提交。

模型目录工具在有结构版本时默认 `view=tree`，无结构时回退 `sections`；HTTP 默认视图不变。`node_id` 展开下级，返回 doc_id/structure_id/node_id 可直接用于 `kb_read_document` 的 `mode=node`。`view=blocks` 保留逐块目录，旧章节视图保留 section_id。目录仅是导航，不分配正文引用；概述和多目标问答优先搜索证据，不必先逐层遍历目录。按节点读取严格保持原文顺序，相关性节选只在问答检索中进行。

```json
{"kb_id":"kb_example","targets":[
  {"doc_name":"report.pdf","mode":"formula","formula_number":"10"},
  {"doc_name":"report.pdf","mode":"formula","formula_number":"11"}
]}
```

完整文件名在绑定库内唯一时解析为文档 ID，重名需明确选择；不从相似文件名猜测。首次读取或召回固定请求的 parse_id、structure_id、index_run_id。期间发布新版，旧版仍可按原定位读取和检索，查询在 SQLite 中验证发布与权限；不能将新旧结果混用。删除文档后即使已有缓存也不能继续复用，包括导航标题和覆盖标签。

## 层级检索与证据覆盖

按以下顺序处理一次问答：

1. 绑定知识库、明确文档/页/节点范围，固定已发布版本。
2. 显式编号直接定位；其余问题融合全局 Dense、Sparse、字面及导航索引，再做相关性排序。目录软路由不成为排除全局结果的唯一门槛。
3. 命中章节或陈述后选择相关内容单元；公式保留条件与编号；需要证明时优先分配证明证据预算，取各证明的起点、结尾及有界中间段。子段保留连接语、紧随公式及编号，并提供可直接读取的节点入口，不只抽取零散句子。显式证明结束标记之后的评论归入独立段落。命题编号查询同时纳入后文明确引用该命题的上下文，例如限制、修订或反例；这种关系只证明存在引用，不自动判断真伪或标为证明。
4. 仅对实际已提供的来源区间去重，预算未容纳的候选不记为已读；同一单元的不同子查询共享证据，不重复占用核心包份额。不同文档不合并。显式范围复查不改动请求位置。多目标先提供核心包，再追加细节，超限的完整公式不拆成残片。
5. 同一请求账本记录已定位、部分提供、已提供的目标范围及缺口。这里的“已提供”仅指选中证据进入了工具返回，并不表示整个节点已读、证明完整或模型理解正确。按缺口补读有界范围，不强迫顺序通读整章。
6. 独立收尾按文档/版本组织证据，先移除补充包、再撤下完整核心包，不能只截断前半个数组。记录取得但未纳入最终输入的单元和未补齐目标；不增加语义核对模型调用，也不因语义核对拦截回答。

树由程序生成，当前不是完整逻辑语篇树，也不采用整篇模型摘要树。条件与证明归属仍可能受 OCR、编号缺失和异常排版影响；保留依据供检查，不能宣称目录层级消除了语义错误。检索中的证明节选带 `sampled` 与单元来源块数，只有显式按节点续读才按完整来源顺序逐步返回。

结构模式及超参数：`KB_RETRIEVAL_MODE=hybrid_structure`（默认）、`flat`（平面对照）、`tree_only`（仅目录排序对照）；`KB_ROUTE_DOC_TOP_K=3`、`KB_ROUTE_NODE_TOP_K=6` 控制导航候选，`KB_UNIT_MAX_CHARS=4000`、`KB_NODE_PREVIEW_CHARS=120` 控制段落组与字面预览；`KB_PROOF_PASSAGE_CHARS=600` 为证明子段的目标长度，遇完整公式会在后续叙述边界分段，并非硬截断。所有模式仍受相同工具预算。结构配置变动需重建索引；实际 `.env` 不会被迁移脚本覆盖。

扩展知识库列表提供“层级目录”入口，支持展开、读取此节点、续读和原页查看。该操作是用户预览，不计作聊天模型已读。能力接口增加 `kb_structure_version=1` 和 `kb_evidence_bundles_version=1`。旧库不自动批量重建；需用户主动点击重建索引，构建期间原版本仍可使用。

`page` 为从 1 开始的物理页，与 `printed_page` 印刷页码分开；字符范围为 Python `[offset,end)`；表格行从 0 开始、右端不包含。按 `next_read` 续读，不用相似度搜索代替已知定位。自然下一块只是导航，不代表必须阅读全文；仅返回片段被截断等实际缺口触发有界补读。公式重号须加页或章节范围，不擅自取第一条。批量目标分别返回状态，单个目标失败不抹去其他成功证据。

跨页关联仅在同章节、页边界、列位置和表格表头等结构条件吻合时建立。表格保留行列跨度和来源行；无显式 `th` 的前导行仅作为上下文，不声称已经证明其表头语义。缺少单元格坐标时只高亮块。引用弹窗展示本轮提供的准确范围、关联块、警告和原页图；未读取的关联块不标为模型已读。

命题、定理、引理、推论及对应英文标签另提供可选结构上下文：同解析版本、同章节内，从编号起点到下一编号陈述或章节标题前，允许跨页读取条件、公式和证明。该范围只是阅读线索，不保证数学论证完整或正确；无明确边界时不跨章节扩大。它与不可拆开的“公式＋编号”“表头＋目标行”“已保存的续接段落”分开，不能把整段证明误当一个不可裁剪的公式单元。

模型证据采用公共 `documents` 加 `evidence`：文档 ID、解析版本、文件名及共同警告按文档保存一次，`evidence.doc_ref` 只在本次工具结果内有效；每条证据保留自己的引用号、物理/印刷页码及字符范围。服务端和前端来源档案仍保留完整信息及坐标，旧证据格式可以恢复。论文原有参考文献号用“原文文献〔3〕”表达，系统 `[3]` 只用于本轮实际返回的证据，不互相替代。

证明搜索预览只附一个直接读取入口，其他未读子段保留在请求覆盖账本，不在每条预览中重复展开全部参数。按节点读取将同一目标的连续原文合并为一条证据，保留各块准确范围；超出预算后仍用节点游标续读，不改变块内字符位置。多个目标共享单次预算，不保证一次就能读完所有证明。

公式密集的证明另有“证明叙述导览”子节点：程序从证明原文中选出叙述段落，保留准确来源，不生成新的摘要或数学结论。关键步骤检索优先提供这个贯穿证明的入口，避免顺序抄写开头公式就耗尽预算。它标为 `proof_route`，明确不包含完整独立公式；完整证明、分段及单独公式仍可读取，不能据导览宣称已核验全部推导。截断预览的读取入口接着已显示范围继续，不从头重复。

独立收尾先在相同文档和解析版本内合并各次工具证据，再移除被完整正文覆盖的短预览。正文补救同样按完整输入预算裁剪，不因某次工具结果超过固定字符数就提前删除其最后一个目标；去重不跨文档或解析版本，不重分配已有引用号。

## 预算和限制

| 配置 | 默认 | 含义 |
| --- | ---: | --- |
| `KB_TURN_TOKENS` | 4000 | 每请求全部 KB 工具返回累计预算 |
| `KB_SEARCH_TOKENS` | 1000 | 单次搜索 |
| `KB_READ_TOKENS` | 2000 | 单次读取，所有批量目标共享 |
| `KB_DIRECTORY_TOKENS` | 400 | 单次目录 |
| `KB_READ_MAX_TARGETS` | 4 | 单次读取目标数，每个目标占一次工具执行额度 |
| `KB_DECISION_MAX_ROUNDS` | 4 | 正常工具决策轮数 |
| `KB_RECOVERY_MAX_ROUNDS` | 2 | 仅有客观缺口时允许的额外 KB 修复/补读轮数 |
| `KB_MODEL_CALL_LIMIT` | 8 | 实际模型调用累计上限，含传输重试、收尾和一次空正文补救 |

- 上述配置都是正整数，非法值启动时报错；调整后重启后端，对新请求生效。存量请求重试沿用开始时的配置，不热更新或重置预算。单次实际额度取工具上限、本请求剩余额度、聊天实际剩余输入空间三者最小值。增大 KB 上限不会扩大模型上下文窗口。
- 正文与序列化元数据用同一个请求 Token 计数器计量。`chat_kb_runtime` 保存配置快照、已用额度、模型/工具次数、版本及读取范围，工具结果和账本一起落库。迁移前使用 SQLite 一致性备份，不修改原文。
- 分词服务中途超时并切换估算时，最终返回再次核算并缩减已选证据；仍能容纳的部分保留，引用档案和未读范围同步更新，不将超限整批误报为“没有资料”。
- 整页/章节读取过滤已标记的页眉页脚等索引排除块；显式指定块或字符范围仍可读取这些内容。批量目标轮流纳入证据，避免第一个长章节耗尽所有后续目标的正文空间；每项返回可用块数、已提供块数和是否局部读取，仍以准确范围判断是否已读。
- 已完成步骤在请求恢复时复用，不重复计费；模型重新发起相同 KB 调用会重新校验权限并计入返回预算，不能靠缓存绕过。总工具执行仍最多 12 次、搜索子问题最多 8 个；增加补读不增加网页或历史工具权限。
- 升级前失败请求若没有配置快照，首次恢复时建立快照，继承旧工具结果可恢复的 Token/工具用量。旧版没有保存实际模型调用次数，不能追溯证明升级前调用上限；严格对比验收应使用升级后新建请求。
- 读取进度只表示实际已提供范围，不代表语义正确。已请求公式缺失、参数错误、明确字符/行范围被截断等可触发最多配置次数的补读；重复无进展即收尾。搜索中首位候选因预算未完整纳入时记录 `not_provided` 和可复用入口，不用更短的低排序标题冒充已提供正文；补读完成按实际字符范围清除缺口，不要求调用参数写法完全相同。浏览页、章节或整块时的剩余范围标记为可选续读，不因材料尚未通读就强迫已答完的模型继续调用。新目录提供了新的定位入口也算进展，但不会抹去另一个工具尚未修正的错误。正常回答不额外调用模型复核。
- 表格目标行补齐保存的表头、单位及合并单元格来源；公式保留与编号的关联；正文自动补齐仅使用已保存的段落续接关系。额外命题上下文通过 `related` 显式展开。完整证据单元超限时明确保留缺口，不把残缺公式、表格或续接句当完整证据；显式字符范围仍逐字对应原文切片。
- 收尾输入按文档、解析版本分组。正文引用编号只与此次实际可见证据核对，不做语义复核；未知编号不隐藏正文、不自动改引、不变成可点击的对应来源。代码和数学内容不作为普通正文引用检查。
- 精排分仅作相关性排序，RRF 不套用相同绝对阈值；精确编号不存在时不拿相似编号冒充。
- OCR 文本是派生结果，不保证公式、标点或数字准确。上游无法判定截断时保留未知和警告，不能标记“无截断”。
- 不确定的跨页段落和表格保持独立，不伪造关联；块级坐标不能证明某个表格单元格的精确位置。
- 同章节的字段记录关联属于结构线索，不保证任意排版的对象归属都正确；复杂嵌套、图中节点/箭头仍需原页核对。当前不做图片语义检索。
- 文件目录、解析覆盖、工具实际读取范围是不同概念。完整解析也不等于模型已阅读全文。
- 默认最多 500 页，目标 144 DPI、单页 1200 万像素、8 MiB 请求及响应；后端默认单任务并发。配置在 `backend/config/.env.example`。
- 沿用项目现有单后端进程运行方式；尚未支持多个后端进程共享任务调度。

当前改造须先通过隔离环境回归与真实文档验收，再启用业务后端；模型部署开机自启与其他固化工作不在本轮范围。
